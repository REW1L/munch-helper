# Story 6.5: Room History Loads in the App

Status: ready-for-dev

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a player,
I want the app to load room history as I browse it,
so that I can move through recent and older session events without leaving the room flow.

## Acceptance Criteria

1. **Given** the Room View, **when** I tap the "Log" action button, **then** the app `router.push`-es to a new Room History (Log) route at `frontend/app/munchkin/[roomNumber]/log.tsx` (registered in `[roomNumber]/_layout.tsx`), and the previously-hidden Log button in `[roomNumber]/index.tsx` (`<TouchableOpacity style={[styles.logButton, { opacity: 0 }]}>`, currently no `onPress`) is **made visible and wired** — opening the screen is a standard stack push and the back affordance returns to the Room View (the `(battle)` route's `presentation: 'modal'` is **not** used here — Log is a plain stack push per UX 12.5).
2. **Given** the Room History screen mounts with a valid `roomId` (from the `[roomNumber]` route param, same `Array.isArray(...)` normalization as `index.tsx`/`(battle)/index.tsx`), **when** it first renders, **then** the app issues **exactly one** first-page request `GET /logs?roomId=<roomId>` (no `before` cursor, no explicit `limit` — server default `50` per Story 6.4 AC 3) via a **new** `frontend/api/logs.ts` `apiRequest` wrapper consumed by a **new** `useRoomLogs(roomId)` hook; the `roomId` is URL-encoded (`encodeURIComponent`) exactly like `getActiveBattle`/`getCharactersByRoom`.
3. **Given** the first page has loaded, **when** the user scrolls to the end of the history list, **then** the next page is requested as `GET /logs?roomId=<roomId>&before=<id of the last entry currently held>` — the cursor is **derived client-side from the last entry's `id`** (Story 6.4 AC 9 contract: there is **no** server `nextCursor`/`hasMore` field — do not invent or expect one); a returned page with **fewer than the page size (`50`) items, including `[]`,** is the **end-of-history** signal and no further automatic next-page requests fire; pages are appended in order with **no duplicate or overlapping entry** across page boundaries (relies on Story 6.4's **exclusive `before`** — the client must not additionally de-dupe or re-sort).
4. **Given** an in-flight request, **when** another end-reached fires, **then** **no concurrent/duplicate next-page request** is issued (guard on the in-flight/`isFetchingNextPage` state); requests support cancellation via the query `AbortSignal` (passed into `apiRequest`, mirroring `getActiveBattle(roomId, signal)`).
5. **Given** the first-page request fails, **when** the error surfaces, **then** the screen shows a **recoverable** error state with a **Retry** affordance that re-issues the first-page request (not a dead end) — consistent with the existing "Error state · Retry" pattern (e.g. the Room View connection-lost retry / `(battle)/index.tsx` `errorText`); **given** a *next-page* request fails, **then** already-loaded entries **remain visible** and a retry for the next page is offered **without discarding loaded history**.
6. **Given** any request is in progress, **when** the view renders, **then** it shows a loading state **appropriate to the view**: initial load → a primary loading indicator (e.g. `ActivityIndicator` + label, matching the `(battle)/index.tsx` `stateBlock` pattern using `AppTheme` tokens); next-page load → a **distinct** in-list/footer loading indicator; loading and error states are **mutually exclusive** (never both at once), and loading is not shown once data is present and the query is idle.
7. **Given** the Story 6.4 response contract, **when** the response is parsed, **then** it is treated as a **bare JSON array** (no `{ data }`/`{ items }` envelope — do not unwrap) of entries typed with **`id`, `roomId`, `eventType`, `actorId`, `summary`, `payload`, `occurredAt`, `createdAt`, `updatedAt`**; `payload` is retained **intact and untransformed** (Stories 6.6/6.7 render character/battle rows from it); the array's **newest-first order is preserved as returned** (no client-side re-sort); `eventType`/`payload` shapes are typed permissively enough to not block on 6.6/6.7's render needs (do not over-narrow `payload`).
8. **Given** the cross-story boundary, **when** this story is implemented, **then** it **does NOT** render `LogEntry` rows / per-event variants, the empty-state copy ("No events recorded yet."), character avatars/field-diff rows, battle-event rows, or battle drill-in (all **Stories 6.6 / 6.7**) — the screen renders the **loading / error+retry / paginated-list-container** scaffolding with a clearly-marked, minimal render seam (e.g. a placeholder list that 6.6/6.7 replace); existing Room View character/battle flows, `index.tsx` behavior other than revealing+wiring the Log button, and all other routes are **unchanged**; **no new dependencies / lockfile churn** (TanStack Query 5.90.21 `useInfiniteQuery` already available).
9. **Given** the quality gate, **when** `npm test` / `npm run test:coverage` run from `frontend/`, **then** co-located `api/logs.test.ts` + `hooks/useRoomLogs.test.ts` are discovered by the default `vitest.config.ts` (`include: ['**/*.test.{ts,tsx}']`, coverage `include: ['api/**','config/**','hooks/**']`) and the **70% line floor still passes** (these two files are the primary coverage targets — the `log.tsx` route file is **not** coverage-counted and its test lives under `frontend/__tests__/app/...` run by `vitest.room-route.config.ts` via `npm run test:room-route`, **never** inside `frontend/app`); tests assert real behavior (page-1 on mount, scroll→cursor page-2, short/empty page → stop, first-page error → retry, next-page error keeps history, missing/blank `roomId` → no request) against a **mocked transport** (no live backend).

### The Story 6.4 contract this story consumes (lock onto it — AC 2, 3, 7)

From Story 6.4 (AC 1, 2, 9 + its Dev Notes "Recommended response shape"):
- **Page 1:** `GET /logs?roomId=X` → `200` **bare JSON array** (no envelope), **newest-first** (`_id`-desc), ≤ `50` entries (server default).
- **Next page:** `GET /logs?roomId=X&before=<id of last entry received>`. Cursor is **client-derived** from the last entry's `id`. `before` is **exclusive** server-side — the next page's first item is strictly older, **never** a repeat — so the client must **not** de-dupe or re-sort.
- **End-of-history:** a returned array with **fewer than `50` items (including `[]`)**. Client stops paginating. There is **no** server `nextCursor`/`hasMore` — do not expect or synthesize one.
- **Entry shape:** `id` (never raw `_id`), `roomId`, `eventType`, `actorId`, `summary`, `payload`, `occurredAt`, `createdAt`, `updatedAt`. `payload` carries all display context (6.6/6.7 render from it — keep it intact, `unknown`-typed, untransformed).
- **Errors:** `{ message: string }`, `400` (bad/missing `roomId`/`before`) / `404` / `502` (never `500`). `apiRequest` already surfaces `responseBody.message` into `ApiError.message`, so `errorMessage` will carry the server message.

> **Variance discipline:** Story 6.4 is `ready-for-dev` (not `done`); these are the *documented* names. If 6.4's delivered backend/`README` differs, conform to the **real** delivered shape and note it in Completion Notes (do not "correct" 6.4). This is a contract dependency, **not** a HALT — implement + unit-test against the locked contract with mocked transport now.

### Use `useInfiniteQuery` — this is the codebase's first one (AC 2–6)

No existing hook paginates; `useRoomBattle`/`useCharacters` are single-shot `useQuery`. TanStack Query **5.90.21** is already a dependency — use `useInfiniteQuery` (v5 API: **`initialPageParam`** + **`getNextPageParam`** are required; v5 renamed/restructured vs v4 — do not copy v4 snippets). Cursor pattern:
- `initialPageParam: null` → page 1 has no `before`.
- `getNextPageParam: (lastPage) => lastPage.length < PAGE_SIZE ? undefined : lastPage.at(-1)?.id` → `undefined` cleanly disables `hasNextPage` (the AC-3 end signal). One `PAGE_SIZE` constant (default `50`) is the single source for both the request and this threshold — **no magic numbers** ([Source: _bmad-output/project-context.md] "Avoid hidden magic values").
- `queryFn: ({ pageParam, signal }) => getRoomLogs(roomId!, pageParam, signal)` — pass `signal` to `apiRequest` (cancellation parity with `getActiveBattle(roomId, signal)`).
- Flatten via `data?.pages.flat() ?? []`. **Preserve order; never client-sort/de-dupe** (6.4's exclusive cursor owns correctness — AC 3/7).
- Concurrency guard (AC 4): `loadNextPage` calls `fetchNextPage()` only when `hasNextPage && !isFetchingNextPage`. `onEndReached` can fire repeatedly during a fling — the guard is mandatory or you get duplicate pages.

Hook return shape: follow the **exact** ergonomics of `useRoomBattle`/`useCharacters` — a `useMemo`-wrapped object, `useCallback` for `loadNextPage`/`refresh`, an explicit exported `UseRoomLogsResult` interface, `getRoomLogsQueryKey` factory `['roomLogs', roomId] as const`, `isLoading = q.isLoading || (q.isFetching && entries.length === 0)`, `errorMessage = error instanceof Error ? error.message : null`. `refresh()` = `invalidateQueries`+`refetch` on the key (powers the first-page Retry). ([Source: _bmad-output/project-context.md] "Use TanStack Query for server-state; keep query defaults aligned with app-level config"; "Preserve React hook discipline".)

### Conventions to honor ([Source: _bmad-output/project-context.md] + architecture)

- **Frontend is strict TS** — explicit boundary types: exported `LogEvent` interface, exported `UseRoomLogsResult` interface, explicit `getRoomLogs` return type. Do not normalize backend non-strict habits in.
- **Layered boundaries:** transport in `frontend/api/logs.ts`; server-state orchestration in `frontend/hooks/useRoomLogs.ts`; route composition in `frontend/app/.../log.tsx`. The route must not call `apiRequest` directly; the hook must not contain `StyleSheet`/JSX. ([Source: architecture/...#frontend layered boundaries]; project-context "frontend/api for transport, hooks for orchestration, app for routes".)
- **TanStack Query** for all server state; align defaults with app-level `QueryClient` (no per-query retry/staleTime overrides unless a clear reason — tests use `retry:false` only in the harness, not in the hook).
- **Expo Router:** `app/**` is route-only — no test files, no shared non-route modules under `app/`. Route file default-exports the screen component.
- **AppTheme tokens only** — no hardcoded colors/spacing; pure `StyleSheet.create` with `AppTheme` (UX 11.1; project-context). Reuse `(battle)/index.tsx` token choices for visual consistency.
- **Minimal, localized edits** — new files + `_layout.tsx` one-line registration + the single Log-button reveal/wire in `index.tsx`. No opportunistic refactor of `index.tsx`/`_layout.tsx`, no dependency/lockfile churn, no realtime wiring.
- **Stable error handling:** narrow `unknown` errors (`error instanceof Error`), surface `ApiError.message`; don't swallow — show the recoverable error state.
- **Docs-in-same-change** if a route/api index doc exists (Task 5).

### Testing standards summary

- Mock the **transport boundary only** (`@/api/logs` `getRoomLogs`, or `apiRequest`/`fetch`) — never mock the unit under test (hook logic / route render). No `mongodb-memory-server`/real network — frontend tests are jsdom + mocked I/O (`useRoomBattle.test.ts` is the canonical pattern).
- One success + one failure path per behavior (project-context "new hooks: ≥1 success + ≥1 failure"): page-1 vs cursor page-2; short/empty page → stop (no extra call); concurrency guard → single request under double `onEndReached`; first-page error → `errorMessage` + `refresh` re-issues; next-page error → loaded entries retained; no `roomId` → zero requests.
- **Highest-value assertions (make explicit, not incidental):** (1) the next-page request's `before` equals the **last currently-held entry's `id`** (guards the AC-3 client-derived-cursor contract); (2) a `< PAGE_SIZE`/`[]` page sets `hasNextPage` false and a subsequent `loadNextPage()` issues **no** request (guards runaway pagination + the end-of-history contract); (3) double `loadNextPage()` while fetching ⇒ exactly one transport call (guards AC-4 duplicate-page bug).
- Coverage focus = `api/logs.ts` + `hooks/useRoomLogs.ts` (the only coverage-included new files). Assert behavior/contracts, not internals. **70% line floor is a CI hard gate — do not lower it** ([Source: _bmad-output/project-context.md]; [Source: architecture/implementation-patterns-consistency-rules.md#Test Coverage Gate]).
- Deterministic only — drive async via `waitFor`; no timer/network flakiness; `QueryClient` `retry:false` in the test harness so failure-path assertions are immediate.
